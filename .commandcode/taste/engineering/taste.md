# Taste — Engineering

- Generated artifacts must always be regenerated by their generator script, never hand-edited; add a CI drift gate (`git diff --exit-code` after regeneration) and make the generator fail loudly on unknown input (e.g. missing per-release metadata) rather than emitting a wrong file. Confidence: 0.85
- Fixes root causes and aligns the implementation with the written spec / shared fixture contract rather than loosening the assertion; when a test contradicts the spec, the spec wins and the test is corrected. Confidence: 0.8
- Keeps every version declaration consistent across the repo (package.json files, pyproject, lockfiles, FastAPI app version, MCP ClientInfo, OpenAPI spec, generated client types, release notes). Confidence: 0.8
- Expects the parallel editions (Docker/Python server and Desktop/Rust app) to stay in parity, with parity checks scripted and wired into CI rather than checked by hand. Confidence: 0.75
- Pins build inputs explicitly per target (platform, per-target checksum, pinned version) instead of deriving them from the host machine — a wrong-arch artifact must never be produced silently. Confidence: 0.75
- Prefers removing duplicated implementations over keeping both copies (extract to a helper module and re-export). Confidence: 0.65
- Prefers suppressions (`noqa`, eslint-disable) to carry a short reason for why the broad except is intentional. Confidence: 0.7
- Keeps Japanese docs and their English mirrors updated together as part of the same change. Confidence: 0.75
